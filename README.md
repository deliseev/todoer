# ToDoer

Это учебное приложение управления задачами на Go. Оно строится снизу вверх — от доменной модели к микросервисной архитектуре — и служит полигоном для TDD и DDD: цель не в готовом продукте, а в том, чтобы пройти весь путь на живом коде и защитить каждое решение перед самим собой.

## Цели и задачи

Главная цель — пройти путь и понять на каждом шаге, почему сделано именно так. Отсюда задачи:

- выделить доменное ядро и оградить его от хранилищ, транспорта и фреймворков;
- поднять над ним сценарии использования, не пустив в них ни одного доменного правила;
- добавить инфраструктуру и транспорт так, чтобы их можно было заменить, не трогая домен;
- разнести получившееся по ограниченным контекстам и связать доменными событиями;
- записывать каждое решение вместе с причиной — и с историей ошибки, если она к нему привела.

## Ограничения, заданные владельцем проекта

- **Только стандартная библиотека.** Никаких внешних зависимостей — ни для тестов, ни для UUID, ни для чего-либо ещё. `go.mod` обязан оставаться без блока `require`.
- **Строгий TDD.** Сначала падающие тесты, потом реализация. Код не пишется, пока тест на него не показал красноту.
- **Идентификаторы английские, комментарии и названия подтестов русские.**
- **Идиоматичный Go 1.26 без устаревших конструкций.**

Ограничения намеренно неудобные: без библиотек приходится разбираться, как устроено то, что обычно берут готовым.

## Что сделано

- **Домен** — агрегат `Task`, значимые объекты, валидные по построению, конечный автомат статусов и доменные события.
- **Сценарии использования** — восемь операций над задачей с оптимистичной блокировкой, авторизацией по владельцу и публикацией событий после записи.
- **Инфраструктура** — хранилище в памяти, системные часы, заглушка публикатора; поведение порта хранилища описано отдельным набором тестов, через который прогоняются обе реализации.
- **HTTP-API** — шесть маршрутов: создать задачу, прочитать, частично изменить и провести по статусам.
- **Команда** — веб-сервер с корректной остановкой по сигналу.

Всё это покрыто 550 подтестами, зелёными под `-race`, и прошло два захода код-ревью.

Чего пока нет и это известно: аутентификации (клиент называет себя заголовком), персистентного хранилища (остановка стирает все задачи), списков и фильтров, идемпотентности создания. Отложено сознательно — причины записаны в [PLAN.md](PLAN.md).

## Как попробовать

```bash
go run ./cmd/todoer          # слушает :8080

curl -s -X POST localhost:8080/tasks \
  -H 'X-Owner-ID: user-42' -H 'Content-Type: application/json' \
  -d '{"title":"Купить молоко","priority":"high"}'
# {"id":"dd1d6272e30193f5df9834838044a5d8"}

curl -s localhost:8080/tasks/dd1d6272e30193f5df9834838044a5d8 -H 'X-Owner-ID: user-42'
```

Остальные маршруты, разбор ответов и отказов — в [DEVELOPMENT.md](DEVELOPMENT.md).
